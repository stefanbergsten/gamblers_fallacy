# Mandatory Project Rules — Proposed Technical Enforcement

These are agreed project hard rules. UAF formal approval, executable enforcement and acceptance results remain pending. Rules apply to humans, agents, processes, scientific computations and generated outputs.

## GF-ARCH-001 — Universal Broadcast

Every meaningful managed activity MUST have authoritative, traceable, broadcastable records: environment observation, filtering, signals, predictions, decisions, simulations, calculations, software changes, memory/feedback changes, authorization, agent communication, errors, failures, evaluation, verification and governance. Record source/run/event IDs, timestamps, owner, versions, policy, inputs/outputs or protected references, status and evidence. Publish authorized projections, not invented agent cognition or visual animations mistaken for work. "Everything" does not mean expose private data or hidden model reasoning. Delivery failures and unverified/blocked states must remain visible.

**Acceptance:** complete enumerated event coverage; source reconciliation; access checks; negative/error-path tests; durable records; replay.

## GF-ARCH-002 — Playback-Native Visualization

Playback MUST be the primary instrument to visualize complex changing behavior, predictions, beliefs-as-reported, learning/adaptation, agency, inconsistencies, uncertainty and emerging patterns. Synchronize data across the seven-stage control loop. Distinguish: historical reconstruction (authoritative events), computational re-execution (pinned versions, potentially divergent), and counterfactual simulation (hypothetical). Show missing records, incompatible versions, unverified claims and failed transitions. Temporal order is not causal proof.

**Acceptance:** source-record reconciliation, reconstruct historical effective authority and agent/model context, version-accurate timelines, duplicate/out-of-order event recovery, and paired comparisons with explicit mode labels.

## GF-ARCH-003 — Evidence-Proven Claims

Every claim presented as established MUST have appropriate independently checked, retrievable evidence. Claim metadata MUST include stable ID, exact assertion, class (mathematical/empirical/causal/operational/etc.), source provenance, assumptions, scope, method, verifier ID, evidence references, uncertainty where meaningful, timestamps and versions. Lifecycle: hypothesis → under_evaluation → verified_within_scope / refuted / inconclusive / withdrawn. Unsupported claims may be broadcast only as clearly marked hypotheses; unknowns remain unknown. An AI's confidence, self-assessment, successful call, schema validation or plausible visualization is not independent proof. Preserve negative evidence; invalidate claims when evidence, methods or premises change.

**Acceptance:** missing-evidence/self-certified claims blocked from verified promotion, evidence integrity tests, version-change revalidation, explicit failures and inconclusive state.

## GF-ARCH-004 — Conformance ≠ Outcome

A structurally valid result MUST NOT automatically be reported as semantically correct. Workflow completion ≠ functional success; successful functional test ≠ intended purpose achieved; positive payoff ≠ good prediction; correlation and temporal order ≠ causation. Each dimension requires its own acceptance criteria and evidence.

## GF-ARCH-004-LC — Logical Consistency

Consequential joint proposition sets, policies, constraints, decisions and conclusions MUST undergo scoped consistency checks. A contradiction requires contextualized propositions, assumptions, time, version and an independently checkable method. Formal unsatisfiability establishes inconsistency **under the formalization**; satisfiability only establishes compatibility within that model, not factual truth. Raw statements and AI-created formalizations must retain separate provenance. Unresolved translations are unknown, not verified. Preserve proof/solver artifacts, conflicting claim IDs, feedback and resolution. Broadcast contradiction events and enable Playback of contradiction lifecycles.

**Acceptance:** contradiction positive fixture, different-time compatible negative fixture, unformalized unknown fixture, checkable evidence, no unauthorized self-certification.

## Enforcement responsibility

UAF contracts and policies → identity and effective authority → orchestrator/tool gates → real execution → independent evaluation → EvidenceGraph → canonical Broadcast → Playback. Prompts, documents and dashboards are not enforcement mechanisms. These rules require explicit machine-readable checks and UAF foundation gates before production-verified status.
